# bridge — ПК-мост SoundCloud Remote

**Стек:** Python 3.12 + pywebview (системный WebView2) + websockets + pycaw.
**Ноль локальной компиляции** — мост запускается прямо из исходников.

> Почему Python, а не Rust/Tauri: на машине разработки неисправная оперативная
> память (MemTest86: 5318 ошибок) — тяжёлые локальные компиляции нельзя вести
> в принципе. Python-мост работает сразу из `run.bat`, правки применяются
> мгновенно. Rust/Tauri-версия сохранена в `../archive/bridge-rust/` — её можно
> оживить после замены памяти, собирая только в GitHub Actions.

**Статус:** Этап 2 готов и **проверен на реальной машине** (smoke-тест 15/15:
рукопожатия, токен, реле команд, обогащение state, системная громкость, GUI).

## Запуск

1. Python 3.10+ (https://python.org, галочка «Add to PATH»).
2. Один раз: `pip install -r requirements.txt` (в папке bridge).
3. `run.bat` (двойной клик) — откроется окно статуса, сервер слушает
   `ws://0.0.0.0:8765/ws`.

Для отладки с консолью: `python main.py`.

## Что уже умеет

- **Трей:** закрытие окна (X) прячет мост в трей — сервер продолжает работать;
  иконка трея: «Показать» / «Выход» (настоящий выход только там). Повторный
  запуск `run.bat` не создаёт второй копии — показывает «уже запущен».
- **Чёрный ящик:** `bridge.log` рядом с кодом — все ошибки и даже нативные
  сбои (faulthandler). Если мост «пропал» — смотреть сюда.
- Сервер по протоколу [`../PROTOCOL.md`](../PROTOCOL.md) (SCR-1):
  - роль `extension` — только loopback, без токена (расширение уже умеет);
  - роль `remote` — телефон с токеном; неверный → `error{auth}` + разрыв;
  - одно активное соединение на роль, новое вытесняет старое;
  - кэш последнего состояния — новый клиент получает снапшот после `hello`.
- Системная громкость: `volume {target:"system"}` исполняет мост (pycaw),
  `target:"player"` уходит расширению.
- QR-код `scremote://connect?host=…&port=8765&token=…`, перевыпуск токена,
  статусы расширения/телефона/трека, слайдер системной громкости.

## Проверка

```bash
python tests\smoke.py
```
Поднимает настоящий сервер и эмулирует обе роли: 15 проверок протокола
(auth, реле, обогащение state, meta, отключение расширения).

## Как устроено

```
bridge/
  main.py          вход: pywebview-окно + js_api
  server.py        WS-сервер SCR-1: роли, токен, ретрансляция, кэш состояния
  volume.py        системная громкость (pycaw, COM напрямую)
  ui/              окно статуса: index.html + app.js + style.css (ванильный JS)
  tests/smoke.py   end-to-end тест протокола (без Chrome и телефона)
  requirements.txt websockets, pywebview, qrcode, pycaw, comtypes
  run.bat          запуск без консоли (pythonw)
```

Замечания:

- **Громкость — однопоточная:** comtypes/pycaw не потокобезопасны, а громкость
  дёргают UI-поллинг и тики расширения. Все COM-вызовы идут через один
  выделенный поток (`volume.py`, очередь + воркер), чтение кэшируется на 2 с.
  Это чинит реальный краш: «ушёл в трей → через ~10 с (реконнект расширения)
  процесс умирал».
- `AudioUtilities.GetSpeakers()` в новых pycaw возвращает обёртку без
  `.Activate` — поэтому идём напрямую через `CoCreateInstance(IMMDeviceEnumerator)`.
- Токен живёт в памяти (перевыпуск кнопкой); персистентность и мастер
  первого запуска — Этап 3.
