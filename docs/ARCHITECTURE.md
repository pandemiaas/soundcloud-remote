# Архитектура SoundCloud Remote

Проект самостоятельный (не ответвление SoundCloud Overlay), но протокол и подход
намеренно близки к «классике»: WebSocket + JSON, локальная сеть, без облака.

Критерии, по которым выбирались технологии: **практичность, скорость (без лагов),
красивый UI, низкое потребление памяти**.

## 1. Схема

```
┌─────────────────────────── Android (Kotlin + Compose) ──────────────────┐
│  Экран подключения (QR/вручную) + экран плеера (портрет/ландшафт)        │
│  OkHttp WebSocket + kotlinx.serialization                               │
└──────────────────────────────┬──────────────────────────────────────────┘
                               │ ws://<IP_ПК>:8765/ws  (Wi-Fi LAN, токен)
┌──────────────────────────────▼──────────────────────────────────────────┐
│  ПК-мост — Python 3.12 (pywebview + websockets + pycaw)                  │
│  • websockets-сервер: роли "remote" (телефон) и "extension"              │
│  • Ретрансляция команд/состояния, токен + QR                            │
│  • Системная громкость Windows (pycaw / IAudioEndpointVolume)           │
│  • Окно статуса на системном WebView2; tray/автозапуск — Этап 3         │
└──────────────────────────────┬──────────────────────────────────────────┘
                               │ ws://127.0.0.1:8765/ws (loopback, без токена)
┌──────────────────────────────▼──────────────────────────────────────────┐
│  Chrome Extension MV3                                                   │
│  • content script: DOM-селекторы SoundCloud, клики, media-элемент       │
│  • background service worker: WebSocket до моста, реконнект, ping       │
└─────────────────────────────────────────────────────────────────────────┘
```

Протокол — [`PROTOCOL.md`](../PROTOCOL.md), единственный источник правды для
всех трёх сторон.

## 2. Стек и почему

### ПК-мост: **Python 3.12** (pywebview + websockets + pycaw)

> Решение пересмотрено на Этапе 2: у машины разработки неисправная оперативная
> память (MemTest86: 5318 ошибок), локальные компиляции (rustc особенно)
> приводят к крашам системы. Поэтому в стек допускается только код, который
> **вообще не требует локальной сборки**.

| Критерий | Как закрывается Python-вариантом |
|---|---|
| Практичность | мост запускается из исходников (`run.bat`), правки применяются мгновенно, собирать нечего |
| Память | ~60–100 МБ: UI рисует системный WebView2 через pywebview, сервер — asyncio |
| Скорость | websockets на asyncio с запасом покрывает трафик пульта (десятки сообщений/с) |
| Красота | тот же подход, что и в Tauri: нативный HTML/CSS в WebView2, полный контроль |

Альтернативы: Rust/Tauri — идеален в рантайме (~40–70 МБ), но требует
тяжёлых локальных сборок (архивная версия сохранена в `../archive/bridge-rust/`,
собрать её сможет CI после замены RAM); Electron — память; Go — компиляция
всё равно нужна локально, GUI-фреймворки сырые.

### Chrome Extension: MV3

- content script читает DOM и дергает кнопки SoundCloud, а также управляет
  медиа-элементом напрямую (`currentTime` для seek, `volume` для громкости
  плеера) — это быстрее и надёжнее эмуляции кликов по полосе.
- background service worker держит WebSocket до моста (Chrome 116+ не убивает
  SW при активном WS + страховочный ping каждые 20 с через `chrome.alarms`).
- Все DOM-селекторы — в одном файле `content/selectors.js`: SoundCloud меняет
  разметку, чинится всё в одном месте.

### Android: **Kotlin + Jetpack Compose (Material 3)**

- Нативно (требование проекта), APK ~4–6 МБ, RAM ~60–100 МБ, анимации на
  панели GPU — UI без лагов.
- Material 3 + динамические цвета = «красиво» без сторонних библиотек.
- Ориентация не фиксируется: портрет — вертикальная колонка, ландшафт —
  двухколоночная раскладка (обложка слева, управление справа) через
  `WindowSizeClass`.
- OkHttp (WebSocket) + kotlinx.serialization; автореконнект с backoff;
  адрес/токен хранятся в DataStore.

### Сборка

**Правило проекта: ничего тяжёлого на машине разработки не собирается.**

- APK: **GitHub Actions** — тег → подписанный релизный APK в Releases
  (keystore в секретах репозитория). Локальная сборка не требуется.
- Мост: компиляции нет вовсе — работает из исходников; CI гоняет
  smoke-тест протокола на каждом пуше.
- Если после замены RAM захотим вернуться к Rust-мосту — собирать его
  тоже только в CI.

## 3. Громкость: два режима

| Режим | Кто исполняет | Что меняет |
|---|---|---|
| `player` | расширение (`mediaElement.volume`) | громкость только плеера SoundCloud |
| `system` | мост (IAudioEndpointVolume) | общая громкость Windows |

Телефон шлёт `volume {target}`, мост сам знает, что `system` исполняет он, а
`player` ретранслирует расширению.

## 5. Риски и как страхуемся

| Риск | Митигация |
|---|---|
| SoundCloud меняет DOM | селекторы в одном модуле; кандидаты списками; `__debug_snapshot` для диагностики |
| Кнопки repeat/shuffle частично за панелью очереди | queue-assist: программно открываем панель, кликаем, закрываем; кэш последнего значения |
| MV3 service worker засыпает | активность WS держит SW (Chrome 116+), плюс ping/alarms |
| Чужие в Wi-Fi | обязательный токен в QR, перевыпуск кнопкой |
| Сон ПК / смена IP | автореконнект с обеих сторон + `sync` после восстановления |
| Неисправная RAM машины разработки | запрет локальных компиляций; мост — интерпретируемый Python; APK — только CI; cargo-сборки отменены |
